# Правила работы с Git

Синтетическая инструкция AI-buddy. Не является внутренним регламентом Авито.

## Ветки и изменения

Для новой задачи создавайте feature-ветку от согласованной ветки разработки. До начала проверьте git status. Не удаляйте чужие незакоммиченные изменения. Делайте небольшие логические изменения и осмысленные сообщения коммитов. Не добавляйте секреты, .venv и node_modules.

## Перед merge request

Запустите тесты и сборку, проверьте diff и отсутствие случайных файлов. Опишите проблему, итоговое поведение и способ проверки. Не выполняйте force push в общие ветки. Слияние выполняется после согласованного Code Review и обязательных проверок. Конкретные имена веток проекта берите из README, а не угадывайте.

## Пример безопасной работы

Перед началом выполните git status, уточните исходную ветку и создайте отдельную feature-ветку. После правок просмотрите git diff, запустите затронутые тесты и добавьте только нужные файлы. Если в рабочей директории есть чужие изменения, не применяйте reset --hard и не удаляйте их. Согласуйте способ продолжения с владельцем изменений.

## Конфликты и секреты

При конфликте сначала поймите назначение обеих версий; если смысл неясен, попросите наставника помочь. После разрешения конфликта повторите проверки. Если секрет попал в коммит, не ограничивайтесь удалением строки: сообщите ответственному и перевыпустите секрет. Не вставляйте ключ в описание merge request.

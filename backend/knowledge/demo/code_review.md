# Code Review в команде Backend

Синтетическая инструкция AI-buddy. Не является внутренним регламентом Авито.

## Подготовка к ревью

Автор создаёт merge request после локальных тестов. В описании указывает цель, изменения поведения, проверку и ограничения. Небольшие изменения проще проверить. Назначьте наставника или согласованного ревьюера. Не отправляйте в ревью реальные персональные данные и секреты.

## Обсуждение замечаний

Ревьюер проверяет корректность, читаемость, права доступа и тесты. На замечания отвечайте по существу; если совет непонятен, попросите пример. Исправления добавляйте в ту же ветку и повторяйте затронутые проверки. Слияние выполняется только после одобрения и зелёных обязательных проверок. Если участники не согласны, обсудите альтернативы с наставником без личных оценок.

## Пример хорошего merge request

Стажёр исправляет проверку email в форме входа. Он создаёт отдельную feature-ветку, добавляет тест на некорректный адрес и описывает: «Раньше форма отправляла пустой email, теперь показывает ошибку до запроса». К описанию прилагает команду тестирования и снимок интерфейса, если внешний вид изменился. Не объединяйте исправление формы с переименованием всех файлов проекта.

## Что проверяем на Code Review

В демонстрационной команде Backend ревью проходит по пяти пунктам: поведение соответствует задаче; API проверяет права пользователя; ошибки обработаны понятным способом; код можно поддерживать; существенные сценарии покрыты тестами. Для миграции отдельно проверяют сохранность существующих записей и совместимость со старой схемой. Секреты и персональные данные в diff недопустимы.

## Замечания, одобрение и слияние

Замечания помечают как блокирующее исправление, предложение или вопрос. Блокирующее замечание нужно устранить либо согласовать альтернативное решение с ревьюером. На предложение можно аргументированно ответить. Для учебного процесса требуется одобрение хотя бы одного назначенного ревьюера и успешные обязательные проверки. Самостоятельно обходить проверки стажёру нельзя. Это правило синтетической команды, а не политика Авито.

## Если ревью задерживается

Сначала проверьте, назначен ли ревьюер и готов ли merge request к проверке. В согласованное рабочее время отправьте короткое напоминание со ссылкой и причиной срочности. Если задача блокирует дальнейшую работу, обсудите приоритет с наставником. Фиксированного срока ответа ревьюера в этом демонстрационном процессе нет.

# Процедура корпоративных доступов

Синтетическая инструкция AI-buddy. Не является внутренним регламентом Авито.

## Заявка на доступ

Стажёр может подготовить заявку на доступ к разрешённому рабочему инструменту. Укажите ресурс, код проекта BACKEND, уровень прав read или write и обоснование. Автора и согласующего определяет backend. Права admin для стажёра в демонстрации запрещены. Запрашивайте минимально достаточные права. Для GitLab дополнительно нужен проект или группа репозиториев.

## Статусы и ограничения прототипа

AI-buddy подготавливает черновик. После проверки параметров стажёр нажимает «Подтвердить создание». Демонстрационный корпоративный адаптер сохраняет заявку в PostgreSQL и возвращает номер. Статусы: pending — ожидает решения, approved — согласована, rejected — отклонена. Согласование не означает выдачу доступа. Настоящие корпоративные системы не подключены. Jira и Confluence в демо согласует назначенный наставник, GitLab — руководитель команды. Это демонстрационное упрощение владельцев ресурсов.

## Если заявка отклонена

Прочитайте причину отказа и уточните минимально достаточные права. Если выбран неверный ресурс, подготовьте исправленные данные и согласуйте их с наставником. Не создавайте несколько одинаковых обращений подряд. Не пытайтесь пользоваться чужим аккаунтом, токеном или обходным адресом, чтобы обойти отказ.

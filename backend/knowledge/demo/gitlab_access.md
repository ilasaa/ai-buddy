# Доступ к GitLab и репозиториям

Синтетическая инструкция AI-buddy. Не является внутренним регламентом Авито.

## Как запросить права на репозиторий

В демонстрационной команде Backend доступ к GitLab запрашивают через заявку на корпоративный доступ. Укажите сервис GitLab, код проекта BACKEND, минимально достаточные права read или write и обоснование. Автора определяет сервер. Для чтения кода запросите минимальные права; запись согласуйте с наставником. Не отправляйте пароли и токены в заявку.

## Согласование и отслеживание

Подготовьте черновик через чат или из задачи адаптации. Подтвердите параметры кнопкой. Демонстрационный адаптер сохраняет заявку в PostgreSQL. Для GitLab согласующим назначается руководитель команды — упрощение владельца проекта. Без назначенного ответственного заявка ожидает маршрутизации. Сохраните номер и проверяйте актуальный статус в «Мои заявки»: pending, approved или rejected. Approved означает согласование, а не выдачу доступа. Реальная выдача прав не реализована.

## Пример заполнения заявки

Ресурс: GitLab, учебный проект BACKEND. Уровень доступа: чтение репозитория для знакомства с архитектурой. Обоснование: выполнение задачи адаптации «Ознакомиться с архитектурой проекта». Согласующий: владелец проекта, которого помогает определить наставник. Название BACKEND синтетическое; настоящий адрес проекта необходимо уточнить, а не угадывать.

## Как проверить выданные права

После уведомления откройте GitLab под рабочим аккаунтом, найдите согласованный проект и попробуйте клонировать его по инструкции репозитория. Если проект не виден или сервер возвращает отказ, запишите обезличенный текст ошибки и номер заявки. Не отмечайте задачу получения доступа выполненной до фактической проверки. Для токена используйте минимальный scope и ограниченный срок, не вставляйте токен в чат.

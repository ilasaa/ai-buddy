# Демонстрация AI-buddy для жюри

Все данные и правила демокоманды синтетические. Используйте разные браузерные профили для трёх ролей, чтобы сессии не заменяли друг друга. Для полного пути выберите `intern-new@ai-buddy.example`; для быстрого обзора уже подготовленных состояний — `intern-ready@ai-buddy.example`. Пароли новых пользователей заданы `DEMO_PASSWORD`, существующие пароли seed не меняет.

## 1. План наставника

Войти `mentor@ai-buddy.example`, открыть «Адаптация команды», выбрать «Новый стажёр». Указать начало сегодня и срок через 90 дней. Название: «Backend: адаптация и первая самостоятельная задача». Ожидания: «Самостоятельно выполнять согласованные задачи с тестами, просить помощь при блокировках и регулярно обсуждать прогресс».

Добавить три цели с критериями:

1. «Освоить рабочее окружение» — получены доступы, настроено окружение, локально запущен сервис.
2. «Выполнить первую самостоятельную задачу» — изучены требования, подготовлено решение, тесты и Code Review.
3. «Освоить командные процессы» — умеет работать с Git, трекером и ревью.

Назначить 8 задач, связав каждую с целью:

| Задача | Цель | Подтверждение |
| --- | --- | --- |
| Познакомиться с командой | Командные процессы | Самостоятельно |
| Прочитать правила коммуникации | Командные процессы | Самостоятельно |
| Отправить заявку на доступ к Jira | Рабочее окружение | Отправка заявки, ресурс Jira |
| Получить доступ к GitLab | Рабочее окружение | Проверка наставника |
| Настроить окружение | Рабочее окружение | Проверка наставника |
| Запустить демонстрационный сервис | Рабочее окружение | Проверка наставника |
| Выполнить первую самостоятельную задачу | Первая задача | Проверка наставника |
| Пройти мини-тест Code Review | Командные процессы | Мини-тест: Code Review |

Указать сроки в пределах плана. Командные OKR уже заданы синтетическим seed; при необходимости добавить цель и ключевые результаты через форму. Нажать «Отправить на согласование».

## 2. Согласование стажёром

Войти `intern-new@ai-buddy.example`. Открыть «Моя адаптация», прочитать ожидания, цели и критерии. Оставить комментарий «Сроки понятны, доступы обсудим с наставником». Нажать «Согласовать план». Проверить статус «Согласован», историю и сохранение после перезагрузки.

## 3. Персональная помощь

При настроенном LLM_API_KEY спросить в чате: «Что мне нужно сделать в первую неделю?» и «Что от меня ожидает наставник?». Сверить ответ с сохранёнными данными. Без ключа показать понятную ошибку настройки; не изображать ответ реальной модели. Платные запросы в ходе самой демонстрации выполняет пользователь; автоматические тесты их не делают.

## 4. Проблема с доступом

Спросить «Как получить доступ к Jira?» — инструкция из RAG. Затем «Подготовь заявку: Jira, BACKEND, просмотр, для задач стажировки». Появляется черновик, заявки ещё нет. Для гарантированной связи с задачей можно открыть соответствующую задачу и нажать «Подготовить заявку на доступ для задачи»: форма сохраняет её ID в черновике. При подготовке через чат явно укажите задачу из вашего плана; backend проверит её владельца. Не угадывайте ID чужой задачи.

## 5. Явное действие

Проверить ресурс, проект, права, причину и связанную задачу. Нажать «Подтвердить создание». Показать реальный номер и `pending` в «Мои заявки». Повторная отправка подтверждения того же черновика возвращает тот же номер. Задача типа «Отправка заявки» завершилась автоматически; задача «Получить доступ» остаётся незавершённой.

## 6. Решение согласующего

Для всех ресурсов войти закреплённым наставником. Открыть «Мои заявки», выбрать заявку, добавить комментарий и подтвердить решение. Стажёр видит `approved` или `rejected`. Подчеркнуть: согласование не выдаёт реальный доступ. Корпоративная интеграция имитируется, выдачи прав нет.

Не показывайте фиктивное получение реального доступа. В учебном сценарии можно описать отдельную подтверждённую проверку на учебном ресурсе и отправить результат наставнику. Черновик заявки ничего не завершает; backend закрывает только задачу с явно заданным условием отправки заявки после её создания.

## 7. Практическая работа

В задаче «Выполнить первую самостоятельную задачу» приложить ссылку на существующий учебный MR либо честно обозначенный синтетический результат. Отправить на проверку. Статус становится «На проверке», процент выполненных задач пока не увеличивается.

## 8. Проверка наставником

Войти наставником, выбрать стажёра и задачу. При необходимости вернуть с комментарием «Добавить тест граничного случая». Стажёр видит замечание и повторно отправляет исправленный результат. Наставник подтверждает. Показать историю автора, комментария и результата, затем новый процент прогресса.

Для простых задач показать самостоятельное подтверждение. Для мини-теста — неуспешную попытку с объяснениями и повторную успешную: ключ не передаётся браузеру заранее, проверяет backend.

## 9. Актуальный следующий шаг

Спросить «Что мне делать дальше?». Сверить рекомендации с текущими незавершёнными задачами. Заблокированную задачу обсудить через форму «Вопрос наставнику»; наставник отвечает в карточке. На второй неделе отсутствующий/несогласованный план не получает искусственную отметку выполнения.

## 10. Обзор наставника

Показать прогресс, проверки, блокировки, просрочки, заявки и командные OKR. Достижение цели наставник подтверждает отдельно, когда все связанные задачи завершены и критерии проверены. Приложить подтверждение критериев.

Открыть новую версию согласованного плана, изменить ожидания или задачу, отправить на повторное согласование. Показать сохранённый предыдущий снимок и запрет незаметного редактирования активной версии.

Повторный показ не требует удаления данных или Docker volumes: используйте другую задачу/новую версию. Согласованная заявка не может быть повторно рассмотрена; для отклонённого обращения создайте новый исправленный черновик. Для повторного прохода теста используйте новую назначенную задачу; успешная попытка остаётся в истории.

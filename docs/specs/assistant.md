# Ассистент, итерация 3

Пользователь авторизуется через cookie. Диалоги и история доступны только владельцу.
Персональный контекст формируется из актуальных SQL-моделей, без паролей/ключей/email.
Источники RAG ограничены public либо командой пользователя; при смене доступа исторический
ответ с закрытым источником скрывается. История ограничена количеством и символами.

Общие вопросы используют LLM; задачи — текущий onboarding.overview и доступный инструмент;
внутренние инструкции — RAG. Без подтверждённой информации ассистент предлагает уточнить
у наставника. Известный конфликт Code Review вызывает детерминированный ответ с источниками,
без выбора «правильной» инструкции. reviewed_on берётся только из подтверждённых метаданных,
updated_at индекса не считается актуализацией.

Вопросы о доступах/заявках включают инструменты независимо от наличия источников.
Модель выбирает функцию; валидацию и права проверяет backend. Инструменты не могут
подтвердить или согласовать заявку. Ответ на статус форматируется из текущей БД,
а не из предыдущего текста модели. Один LLM-вызов, до 4 инструментов, без циклов.

[Полный контракт, ошибки и диаграмма](corporate-actions.md).
[Критерии доступа](permissions.md). [Переходы и API](access-requests.md).

Проверяемые сценарии: источник Jira → уточнение параметров → серверный черновик → кнопка
→ реальная заявка → наставник согласует → инструмент получает новый статус.
При prompt injection действие без кнопки не выполняется. При недоступности LLM/БД/embedding
показывается ошибка либо отсутствие подтверждённой инструкции; успех не симулируется.

Ограничение: универсальный семантический маршрутизатор не реализован; выбор инструмента
моделью зависит от провайдера. Реальный smoke с платным ключом выполняется отдельно от автотестов.


## Исправление диалога стажёра

Конфликт документов блокирует ответ только на соответствующий вопрос Code Review.
В списке источников конфликта остаётся по одной ссылке на документ; посторонние инструкции
не выводятся. Оформление доступа/статусы используют инструменты и серверную политику без RAG.
Для инструкции по доступу RAG ограничивается относящимися к сервису документами.
Короткий ответ «BACKEND, редактирование» продолжает оформление, явная другая тема — нет.
Ранее ошибочные ответы о конфликте не передаются LLM при оформлении доступа.

Не требуется знать названия инструментов или read/write. Модель уточняет проект и права
обычными словами. Причина по умолчанию — «Работа над задачами стажировки»; она видна до
подтверждения. Уточнение модели сохраняется. Без вызова инструмента ответ не может
подтверждать создание или сообщать выдуманный статус.

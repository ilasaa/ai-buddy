# SDD: персональный AI-buddy, версия 2

## Назначение и границы

AI-buddy отвечает на русском профессионально, без эмодзи. Он объясняет задачи, процессы и
программирование, но не выдаёт синтетические материалы за регламенты Авито. Действий в
корпоративных системах нет: запрос «создай заявку» получает объяснение процедуры, а не
подтверждение вымышленной операции. Tool Calling не подключён.

## Контракт запроса

POST /assistant/chat принимает message и необязательный conversation_id. Пустые строки,
превышение CHAT_MAX_MESSAGE_CHARS и поля user_id/role запрещены (422). Идентичность берётся
из JWT-cookie; неавторизованный запрос — 401, чужой диалог — 404. CSRF-проверки те же, что
для остальных POST. Возвращаются conversation_id, сохранённое сообщение ассистента, sources,
prompt_tokens/completion_tokens и rag_used.

## Маршрутизация

1. Вопросы о собственных задачах/прогрессе/наставнике получают актуальные данные SQL.
2. Приветствия и явно общие вопросы программирования не требуют поиска.
3. Остальные вопросы консервативно направляются в RAG. Для короткого уточнения добавляется
   предыдущий вопрос пользователя. Эвристики прозрачны и могут ошибаться: это ограничение MVP.
4. Наставники и руководители используют тот же чат со своим профилем; задачи чужих стажёров
   им не передаются. Расширенные полномочия управления пока не вводятся.

## Персональный контекст

Профиль содержит имя, роль, название своей команды, допустимое имя наставника, дату старта,
прогресс и максимум 30 своих задач (название, статус, срок). При усечении передаётся явный флаг.
Email, хеш, ключи и JWT не отправляются модели. История ограничена CHAT_HISTORY_MESSAGES и
CHAT_HISTORY_CHARS; текущее сообщение всегда включается. Контекст — user data, не system.

## Поиск и источники

CPU multilingual-e5-small, passage:/query:, нормализация L2, VECTOR(384), cosine distance.
SQL сначала ограничивает документы public OR team_id=current_user.team_id и embedding_model,
затем сортирует и выбирает top_k. В модель попадают только разрешённые фрагменты в пределах
RAG_CONTEXT_CHARS. Для MVP выбран точный поиск: ANN-индекс не нужен на 12 документах и может
снижать recall при ACL-фильтре. Источники создаёт backend из найденных записей, а не модель.

Порог калибруется scripts.evaluate_rag на размеченных вопросах. Результат и ограничения —
docs/rag-evaluation.txt. Без настроенного порога возвращается 503. При отсутствии результатов
backend возвращает честное сообщение об отсутствии подтверждения без платного запроса,
с пустым sources и rag_used=false. При наличии фрагментов система требует цитаты [1], [2]
и запрещает додумывать отсутствующие корпоративные правила. Наличие близкого фрагмента само
по себе не гарантирует полноту ответа; это требует дальнейшей оценки на расширенной выборке.

GET /knowledge и /knowledge/{id} повторяют серверную проверку области доступа. При изменении
команды старые ответы, ссылающиеся на теперь недоступные документы, скрываются целиком;
их текст не возвращается клиенту и не включается в историю LLM.

## Недоверенные инструкции

System запрещает переопределять роль, исполнять команды из документов, раскрывать секреты и
заявлять об исполненных действиях. Тексты пользователя/документов сериализуются как данные.
Защита промптом не считается полноценной изоляцией: секретов и инструментов у модели нет,
ACL применяется до модели, произвольный HTML не исполняется. Backend не предоставляет
модели административных операций, SQL или файловую систему.

## Ошибки и расходы

- Тайм-аут провайдера — 504; сеть/статус API/пустой ответ — 502; лимит провайдера — 429.
- Нет ключа/модели/калибровки/хранилища — 503 с безопасным сообщением без текста исключения.
- Лимит за скользящие 24 часа — 429. Попытки учитываются PostgreSQL-записями ChatUsage;
  advisory transaction lock предотвращает гонки между workers. Ошибочные внешние попытки
  тоже расходуют локальную квоту. Без ключа квота не резервируется.
- Один ответ на пользователя одновременно; повторный запрос — 409. Клиент отключает
  отправку и выбор другого диалога на время ожидания. Повторная отправка после ошибки явная.
- Ответ максимум LLM_MAX_TOKENS (по умолчанию 1000), timeout 45 секунд, thinking disabled,
  автоматических retry нет. В историю сохраняется usage. Денежный глобальный бюджет не
  гарантируется приложением: владелец отслеживает его в DeepSeek и ограничивает ключ.
- Пара user/assistant сохраняется атомарно только при успехе. Ошибка не создаёт ложного ответа;
  поле ввода сохраняется. Streaming в этой версии отсутствует, индикатор отражает реальный запрос.

## Проверяемые критерии

- Без сессии POST и история возвращают 401; чужой conversation_id — 404.
- Вопрос о своих задачах передаёт актуальный SQL-контекст, не вызывает retrieval.
- GitLab и перефразирование про права на репозиторий находят разрешённый источник в top 5.
- Закрытый документ Analytics не появляется в SQL-результате Backend, LLM или просмотре.
- Несуществующий регламент приводит к отказу без выдуманных правил и без расхода API.
- Ошибки DeepSeek не оставляют половину диалога и не раскрывают внутренний текст исключения.
- Перезагрузка восстанавливает историю; источник открывает существующий разрешённый документ.
- Тесты по умолчанию не обращаются в DeepSeek и не скачивают E5.
- Реальная E5 интеграция запускается отдельно RUN_LOCAL_MODEL_TEST=1.
- PostgreSQL cosine/ACL тест требует pgvector-миграции; пропуск явно указан в отчёте.

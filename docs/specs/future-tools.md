# SDD: будущие корпоративные инструменты (не реализованы)

Первый кандидат — create_access_request(resource, permission, justification).
Аутентификация, user_id и команда должны приходить из проверенной серверной сессии.
Перед выполнением сервер проверяет ресурс и минимальные права, показывает конкретный черновик
заявки и запрашивает подтверждение пользователя. Ключ идемпотентности предотвращает повторное
создание. Ответ содержит настоящий номер и статус только после подтверждения корпоративного API.

get_access_request_status(request_id) разрешает просмотр только владельцу или уполномоченной
роли в своей области доступа. Чужой/неизвестный номер — 404. Нельзя считать отсутствие ошибки
или текст LLM подтверждением выполнения. Тайм-аут оставляет статус «результат неизвестен» с
последующей сверкой по ключу идемпотентности.

Необходимы аудит без секретов, тесты на доступы и повторные запросы, контролируемые тайм-ауты,
строгая схема аргументов и возможность отозвать разрешение. Недоверенный текст документов не
может инициировать инструмент. В текущем приложении инструменты, создание заявок и интеграция
статусов отсутствуют.

# Проверка: две роли и кнопки задач

Ветка `develop`, 15.11.2026. Уточнение пользователя заменяет прежнее разделение наставника и руководителя.

## Изменения

- В API и интерфейсе две роли: `intern`, `mentor`. Назначенный наставник создаёт и меняет планы и цели, задаёт OKR, проверяет задачи, отвечает на обращения и согласует Jira/Confluence/GitLab.
- Полномочия ограничены назначением `intern.mentor_id` и совпадением команды. Роль наставника либо владение командой без назначения стажёра не раскрывает его данные.
- Выпадающий список статусов стажёра заменён кнопками: «Приступить», «Продолжить», «Завершить». Практическая задача завершается после проверки наставником, тест — после серверной оценки.
- Добавлен способ `request`: наставник задаёт ресурс. Черновик ничего не завершает; подтверждённое создание связанной заявки в той же транзакции завершает задачу и сохраняет доказательство с номером. Повтор не создаёт вторую проверку. Задача получения доступа не закрывается отправкой заявки автоматически.
- Миграция `a62411050001` сохраняет старые аккаунты и пароли, переводит `manager` в `mentor`, ограничивает роли, переименовывает автора плана в `mentor_id`, добавляет ресурс задачи и перенаправляет ожидающие заявки назначенному наставнику. Исторические решения и снимки не переписываются.
- Новый seed не создаёт руководителя; существующий бывший аккаунт сохраняется. Точные старые задачи «Оформить доступ к Jira через AI-buddy» получают условие отправки Jira-заявки без сброса текущего прогресса.

## Применение

```bash
sudo docker compose up --build -d
```

Backend применит миграцию перед запуском. После запуска обновить страницу; при необходимости войти заново. Для обычного наставника использовать существующий `mentor@ai-buddy.example` с прежним паролем. Нельзя удалять volumes или пересоздавать базу с потерей данных. Коммит и push не выполнялись.
